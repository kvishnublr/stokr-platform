================================================================================
CRITICAL FIX APPLIED - TRANSACTION ROLLBACK GUARD
================================================================================

ISSUE FOUND IN SCREENSHOT:
"Transaction silently rolled back because it has been marked as rollback-only"

ROOT CAUSE:
When database transactions fail, they roll back SILENTLY without any record
in the signal_execution_tracks table. This means:
- Traders see: order submitted ✓
- System sees: transaction rolled back
- Tracking shows: nothing (silent failure)
- Auto-retry: cannot run (no tracking record)

SOLUTION DEPLOYED:
TransactionRollbackGuardService.java - NEW FILE
- Detects rollback BEFORE it becomes silent
- Records failure to signal_execution_tracks table
- Alerts operations team
- Enables auto-retry to recover

================================================================================
HOW IT WORKS
================================================================================

BEFORE (Silent Failure):
  Order submitted to broker ✓
  Broker accepts order ✓
  Update OMS position
    → Constraint violation! ✗
    → Transaction.rollback() ✓
    → All changes UNDONE (including order creation!)
    → UI shows error message
    → Database shows: no tracking record
    → Auto-retry: cannot run
    → Trader: confused (order was submitted, where did it go?)

AFTER (Visible Failure):
  Order submitted to broker ✓
  Broker accepts order ✓
  Update OMS position
    → Constraint violation! ✗
    → Rollback detected! 🚨
    → recordFailure() writes to signal_execution_tracks
    → Alert logged for operations
    → Auto-retry: enabled and will run in 5 minutes
    → Trader: sees "Signal execution FAILED"
    → System: has complete tracking of what failed and why
