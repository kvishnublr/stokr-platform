================================================================================
        STOKR PLATFORM - CONTABO DEPLOYMENT & PERFORMANCE ANALYSIS
        Complete Step-by-Step Instructions for Production Deployment
================================================================================

DEPLOYMENT PHASES:
1. Backup existing database
2. Pull latest code from GitHub (Release_v1 branch)
3. Build Maven project
4. Stop current service
5. Deploy new JAR
6. Start service and verify
7. Generate 6-day performance report
8. Analyze strategy performance
9. Identify improvements needed
10. Implement and backtest improvements

================================================================================
PHASE 1: BACKUP EXISTING DATABASE
================================================================================

SSH into Contabo server:
  ssh -i your_key root@173.249.55.84

Create backup directory:
  mkdir -p /backup/stokr-platform

Backup current database:
  pg_dump -U postgres -h localhost stokr_platform | gzip > /backup/stokr-platform/backup_$(date +%Y%m%d_%H%M%S).sql.gz

Verify backup created:
  ls -lh /backup/stokr-platform/

Expected output: backup_20260525_183000.sql.gz (file size ~100-200MB)

================================================================================
PHASE 2: PULL LATEST CODE FROM GITHUB
================================================================================

Navigate to platform directory:
  cd /opt/stokr-platform

Fetch latest changes:
  git fetch origin

Switch to Release_v1 branch:
  git checkout Release_v1

Pull latest commits:
  git pull origin Release_v1

Verify commits pulled (should see latest 5 commits):
  git log --oneline -5

Expected output:
  be9d7be Add deployment guide and performance analysis tools
  b73e1c0 PHASES 4-9: Complete platform stabilization
  3568fd0 PHASE 3: Queue Architecture Stabilization
  73232bb PHASE 2: Execution Truth Engine
  bc7f627 PHASE 1 (FINAL): Adjust minimum risk/reward ratio

================================================================================
PHASE 3: BUILD MAVEN PROJECT
================================================================================

Navigate to stokr-bootstrap directory:
  cd /opt/stokr-platform/stokr-bootstrap

Clean previous builds:
  mvn clean

Build new JAR (this takes 2-3 minutes):
  mvn install -DskipTests 2>&1 | tee build.log

Check for successful build:
  tail -5 build.log

Expected output:
  [INFO] BUILD SUCCESS
  [INFO] Total time: 2 min 45 sec

If BUILD FAILS:
  - Check errors: grep -i "error" build.log
  - Check JDK version: javac -version (should be 21+)
  - Check Maven: mvn -v (should be 3.6+)

================================================================================
PHASE 4: STOP CURRENT SERVICE
================================================================================

Check if service is running:
  ps aux | grep stokr-platform | grep -v grep

Stop service gracefully:
  systemctl stop stokr-platform

  OR if using manual startup:

  pkill -f "java.*stokr-bootstrap"
  sleep 5

Verify stopped:
  ps aux | grep stokr-platform | grep -v grep

Expected output: (empty - no running process)

Check port 8080 is free:
  netstat -tlnp | grep 8080

Expected output: (empty - port available)

================================================================================
PHASE 5: DEPLOY NEW JAR
================================================================================

Copy new JAR to deployment directory:
  cp /opt/stokr-platform/stokr-bootstrap/target/stokr-bootstrap-1.0.0-SNAPSHOT.jar /opt/stokr-platform/app/stokr-platform.jar

Verify JAR copied:
  ls -lh /opt/stokr-platform/app/stokr-platform.jar

Expected output: -rw-r--r-- 1 root root 125M stokr-platform.jar

================================================================================
PHASE 6: START SERVICE AND VERIFY
================================================================================

Set environment variables:
  export STOKR_SIGNAL_QUALITY_MIN_RR=1.5
  export STOKR_SIGNAL_COOLDOWN_SECONDS=300
  export STOKR_SIGNAL_QUALITY_MIN_CANDLE_BODY_PCT=0.003
  export DB_HOST=localhost
  export DB_PORT=5432
  export DB_NAME=stokr_platform
  export DB_USER=postgres
  export DB_PASSWORD=root123
  export REDIS_HOST=localhost
  export RABBITMQ_HOST=localhost

Start service (with output logging):
  java -jar /opt/stokr-platform/app/stokr-platform.jar > /var/log/stokr-platform.log 2>&1 &

Wait for startup (30-60 seconds):
  sleep 45

Check service is running:
  ps aux | grep stokr-platform | grep -v grep

Expected output: java -jar /opt/stokr-platform/app/stokr-platform.jar

Check health endpoint:
  curl http://localhost:8080/actuator/health

Expected output: {"status":"UP","components":{...}}

Check logs for errors:
  tail -100 /var/log/stokr-platform.log | grep -i "started\|error\|exception"

Expected output: "Started StokrBootApplication in X seconds"

Verify database connection:
  psql -U postgres -h localhost -d stokr_platform -c "SELECT COUNT(*) FROM strategy_signals;" -c "\q"

Expected output: count = (some number >0)

================================================================================
PHASE 7: GENERATE 6-DAY PERFORMANCE REPORT
================================================================================

Run SQL analysis (generates formatted report):
  psql -U postgres -h localhost -d stokr_platform -f /opt/stokr-platform/PERFORMANCE_ANALYSIS.sql > /var/log/performance_report.txt 2>&1

View report:
  less /var/log/performance_report.txt
  (press 'q' to exit)

OR save to file for review:
  cat /var/log/performance_report.txt

================================================================================
PHASE 8: PYTHON-BASED PERFORMANCE ANALYSIS
================================================================================

Install Python PostgreSQL driver (if not installed):
  pip install psycopg2-binary

Run Python analysis script:
  python3 /opt/stokr-platform/performance_analyzer.py > /var/log/strategy_analysis.txt 2>&1

View analysis:
  cat /var/log/strategy_analysis.txt

This generates:
  - SECTION 1: Overall statistics for last 6 days
  - SECTION 2: Strategy-wise daily performance
  - SECTION 3: Strategy summary (6-day aggregate)
  - SECTION 4: Strategies needing improvement (<50% WR)
  - SECTION 5: Quality gate effectiveness
  - SECTION 6: Recommended improvements (DISABLE/TUNE/KEEP_ACTIVE)

================================================================================
PHASE 9: ANALYZE RECOMMENDATIONS
================================================================================

From the performance report, identify:

1. BOTTOM PERFORMERS (Win Rate < 50%):
   - Disable: Strategies with <45% win rate (critical failures)
   - Tune: Strategies with 45-50% win rate (needs parameter adjustment)

2. MARGINAL PERFORMERS (Win Rate 50-55%):
   - Monitor closely
   - Consider parameter tuning
   - May become good with market conditions

3. TOP PERFORMERS (Win Rate >55%):
   - Keep active
   - Monitor for consistency
   - Can be allocated more capital

4. QUALITY GATE EFFECTIVENESS:
   - Check % of signals passing quality gate
   - Should be 80-95% (filters spam)
   - If >95%, gates may be too lenient
   - If <80%, gates may be too strict

================================================================================
PHASE 10: IMPLEMENT IMPROVEMENTS (IF NEEDED)
================================================================================

Based on analysis, if strategies need tuning:

1. DISABLE Poor Strategy:
   - Edit strategy generator file
   - Change @Service annotation to @Disabled
   - Rebuild Maven: mvn clean install -DskipTests
   - Redeploy JAR
   - Restart service

2. TUNE Parameter Strategy:
   - Edit strategy configuration in application.yml
   - Adjust thresholds (RSI levels, ATR multiples, etc.)
   - Example: Change RSI_OVERBOUGHT from 60 to 65
   - Save and restart service (no rebuild needed if config only)

3. BACKTEST Improved Strategy:
   - Use admin test lab in UI
   - Select improved strategy
   - Select date range (last 6 days)
   - Run backtest
   - Compare metrics before/after
   - Verify win rate improvement

================================================================================
ROLLBACK (IF PROBLEMS OCCUR)
================================================================================

If deployment fails or causes issues:

1. Stop service:
   pkill -f "java.*stokr-bootstrap"

2. Restore database backup:
   gunzip -c /backup/stokr-platform/backup_YYYYMMDD_HHMMSS.sql.gz | psql -U postgres -h localhost stokr_platform

3. Restore previous JAR (if available):
   cp /backup/stokr-platform/stokr-platform-previous.jar /opt/stokr-platform/app/stokr-platform.jar

4. Start service with previous version:
   java -jar /opt/stokr-platform/app/stokr-platform.jar > /var/log/stokr-platform.log 2>&1 &

5. Verify health:
   curl http://localhost:8080/actuator/health

================================================================================
MONITORING AFTER DEPLOYMENT
================================================================================

Monitor these metrics during first 24 hours:

1. Service health every 5 minutes:
   watch -n 5 "curl http://localhost:8080/actuator/health"

2. Error logs in real-time:
   tail -f /var/log/stokr-platform.log | grep -i "error\|exception\|critical"

3. Signal generation:
   psql -U postgres -d stokr_platform -c "SELECT COUNT(*) FROM strategy_signals WHERE created_at > NOW() - interval '1 hour';"

4. Position reconciliation:
   grep "reconciliation" /var/log/stokr-platform.log | tail -10

5. Queue depth:
   grep "queue.depth" /var/log/stokr-platform.log | tail -10
