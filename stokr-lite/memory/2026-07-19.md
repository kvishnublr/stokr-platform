# 2026-07-19 — WebSocket Depth Integration for Bid Parity Auto-Trader

## What we did
Integrated real-time WebSocket bid/ask depth data into the Bid Parity Auto-Trader, replacing REST API polling with sub-second tick updates.

### Backend Changes
1. **KiteTickParser.java** — Fixed MODE_FULL depth parsing (was SKIPPING 120 bytes). Now extracts best bid (price + qty) and best ask (price + qty) from 5 buy + 5 sell depth levels. Fixed `divPrice()` return type (BigDecimal → double via `.doubleValue()`).

2. **TickData.java** — Added `bidPrice`, `bidQty`, `askPrice`, `askQty` fields to entity (persisted to `tick_data` table).

3. **BidParityDepthCache.java** — NEW: ConcurrentHashMap-based in-memory cache. Fed by TickAggregatorService on every WebSocket tick. Stores latest bid/ask price + qty per symbol.

4. **TickAggregatorService.java** — Injected `BidParityDepthCache`, calls `depthCache.onTick(tick)` on every tick.

5. **KiteInstrumentTokenCache.java** — NEW: Downloads full Kite instruments CSV (37,977 NFO tokens loaded). Maps NFO symbol → instrument_token for WebSocket subscription.

6. **BidParityAutoTrader.java** — Injected `BidParityDepthCache` + `KiteTickWebSocketClient` + `KiteInstrumentTokenCache`. Exit logic now reads from depth cache (real-time WebSocket data) instead of polling REST API. Subscribes all scanned instruments to WebSocket on each scan cycle. Status now shows `wsDepthTicks` count.

7. **OptionArbitrageController.java** — Injected `BidParityDepthCache`. `/bid-parity/live-ticks` endpoint now returns both REST scan ticks AND WebSocket depth ticks (`wsTicks` field).

### Frontend Changes
- Live tick indicator now shows blue pulse for WebSocket ticks, green for REST scan ticks
- `wsTicks` data parsed from API response
- WS tick count displayed in header
